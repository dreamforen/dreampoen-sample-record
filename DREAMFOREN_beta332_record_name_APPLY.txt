DREAMFOREN Beta 3.32 — 시료채취기록지 업체명 표시 수정

적용할 파일: app.js, company_archive.js, index.html (3개)
Supabase SQL 적용이나 서버 폴더 업로드는 필요 없습니다.

적용 순서
1. ZIP 압축을 해제합니다.
2. GitHub dreamforen/dreampoen-sample-record 저장소의 기존 파일과 같은 위치에
   app.js, company_archive.js, index.html 3개를 업로드하여 덮어씁니다.
   ZIP이나 이 안내문 자체를 웹에 업로드하지 않아도 됩니다.
3. GitHub Pages 배포 완료 후 웹에서 Ctrl+Shift+R로 새로고침합니다.
4. 시료채취기록지에서 2026-10-15 저장기록을 다시 확인합니다.
   20261015-15처럼 업체명을 바꾼 기록은 동일한 업체 ID가 확인되면
   저장목록·불러오기 안내·본문이 현재 업체명으로 표시됩니다.

원인
본문은 저장된 업체 ID로 업체현황의 현재 업체명을 표시하지만,
저장목록과 불러오기 안내는 기록 저장 당시의 업체명을 표시하고 있었습니다.
서버의 간단 목록은 업체 ID를 제외하고 조회하여 표시 기준이 서로 달랐습니다.

수정 내용
- 저장된 업체 ID가 현재 업체와 유일하게 일치하면 현재 업체명을 표시합니다.
- 온라인 간단 목록에도 업체·시설 ID를 함께 불러옵니다.
- 업체 정보가 새로고침될 때 저장목록과 불러오기 안내도 다시 표시합니다.
- 업체 ID가 없는 과거 기록을 열 때 직전 화면의 업체·시설 ID를 물려받지 않습니다.
- 업체명에 특수문자가 있어도 글자로 표시합니다.

자료 보존
단순 조회만으로 저장 원본의 업체명·측정값·접수번호·여지번호를 수정하지 않습니다.
현재 이름으로 본문을 확인한 뒤 기존 ‘기록 저장’을 누르면 해당 기록만
기존 저장 절차와 권한에 따라 저장됩니다. 일괄 재저장은 필요하지 않습니다.
자료실, 분석, 시료인수인계대장의 저장·삭제·연동 로직과 직원 권한은 변경하지 않았습니다.
업체 ID가 없거나 중복되어 확인할 수 없으면 저장 당시 이름을 유지합니다.
그 경우 업체를 직접 선택하고 기록을 확인한 뒤 저장해주세요.

확인 범위
첨부 사례를 로컬에서 재현했고, 기기 저장본·온라인 간단 목록·원본 불러오기,
업체 새로고침, 1·2팀 구분, 과거 기록의 ID 잔류 방지를 검증했습니다.
실제 운영 DB에 접속하거나 사이트에 직접 배포하지는 않았습니다.
적용 후 운영 기록 20261015-15에서 최종 확인해주세요.
